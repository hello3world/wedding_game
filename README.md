# 🤘 Свадебный переполох

Многопользовательская мобильная Web-игра для свадебного банкета в рок-стиле. Гости сканируют QR-код, попадают на страницу игры и соревнуются друг с другом в реальном времени — управляя женихом, который ловит радостные моменты семейной жизни и уворачивается от бытовых неприятностей.

![Stack](https://img.shields.io/badge/stack-FastAPI%20%2B%20Canvas%20%2B%20WebSocket-cc0000?style=for-the-badge)

## 📖 Описание

**Свадебный переполох** — это 60-секундная аркада на выживание, где гости свадебного банкета превращаются в настоящих героев рок-концерта! Представьте: жених оказывается на сцене, и вместо того чтобы произносить тост, он уворачивается от тёщи, ловит обручальные кольца и избегает грязных носков.

### Как это работает
1. Гости открывают сайт на телефоне (например через QR-код на приглашении)
2. Вводят своё имя и выбирают команду: **Комата жениха** 👰 или **Команда невесты** 👱
3. Когда ведущий говорит «Поехали!», начинается безумие:
   - Сверху падают разные предметы (эмодзи)
   - Нужно тащить палец по экрану, чтобы двигать жениха
   - Ловишь бонусы 💍🥂❤️ — получаешь очки
   - Ловишь проблемы 👩🧦🎤 — теряешь очки и замораживаешься
4. Результат считается в реальном времени и отображается в общем рейтинге
5. Через 60 секунд — финальный подсчёт очков и побеждает самая мощная команда!

### Особенности
- ⚡ **Real-time мультиплеер** через WebSocket — все видят результаты друг друга
- 🎵 **Рок- атмосфера** — готический шрифт, тёмная сцена, красно-золотые акценты
- 🎮 **Простое управление** — один палец, идеально для мобильных
- 📊 **Живой рейтинг** — лидерборд обновляется каждые 200мс
- 🔗 **Командное соревнование** — счёт ведётся между командой жениха и невесты
- 🏆 **Tie-breaking** — при равенстве очков побеждает тот, кто набрал их раньше

## 🖼️ Как добавить фото жениха и невесты

В проекте есть возможность заменить стандартные спрайты (эмодзи) на реальные фотографии жениха и невесты.

### Где находятся файлы изображений:

В папке `static/img/` лежат ровно 4 файла — по одному на каждую картинку игры.
Имя файла сразу объясняет, **что это** и **чьё это** (`groom` = жених, `bride` = невеста):

| Файл | Что на нём | Где появляется в игре |
| --- | --- | --- |
| `groom-head.png` | 👨 лицо (голова) жениха | спрайт жениха, крутится во время раунда |
| `bride-head.png` | 👰 лицо (голова) невесты | спрайт невесты, крутится во время раунда |
| `groom-victory.png` | 🏆 фото жениха | экран, когда победила команда жениха |
| `bride-victory.png` | 🏆 фото невесты | экран, когда победила команда невесты |

### Как заменить на свои фото:

1. **Подготовьте изображения:**
   - `*-head.png` — вырезанное лицо на прозрачном фоне, PNG, квадратное
     (512x512 или больше) — игра сама обрежет его по кругу
   - `*-victory.png` — любое фото целиком, PNG, горизонтальное (~760x680),
     можно полноростовое с торжеством — масштабируется автоматически

2. **Сохраните свои файлы поверх этих же имен** — код менять не нужно:
   ```bash
   # Скопируйте ваши фото в папку static/img/
   cp мое_лицо_жениха.png    static/img/groom-head.png
   cp мое_лицо_невесты.png   static/img/bride-head.png
   cp фото_жених_победил.png static/img/groom-victory.png
   cp фото_невеста_победила.png static/img/bride-victory.png
   ```
   То же самое делается мышкой: откройте папку `static/img/` в проводнике,
   удалите старый файл и положите свой с таким же именем.

3. **Обновите страницу** в браузере (Ctrl/Cmd+Shift+R, чтобы сбросить кэш).

4. **Перезапустите сервер** (если нужно):
   ```bash
   python -m uvicorn main:app --host 0.0.0.0 --port 8000
   ```

> **Примечание:** Если фото не найдены, игра автоматически использует эмодзи по умолчанию (👨 для жениха, 👩 для невесты).

## 🎵 Музыкальное сопровождение

Фоновая музыка лежит в папке `static/audio/` (формат MP3). Сервер сам проверяет, какие файлы есть, поэтому код менять не нужно: положил файл с правильным именем — и он заработает.

| Файл | Когда играет |
| --- | --- |
| `game-theme.mp3` | во время раунда — сразу после старта |
| `results-theme.mp3` | на экране результатов — после конца раунда |

Сейчас в папке есть только `game-theme.mp3`. Если `results-theme.mp3` отсутствует — финальная тема просто не играет, ошибок не возникает (то же правило действует для обоих файлов).

### Как добавить свою музыку:

1. **Подготовьте трек** в формате MP3 (любая длина — музыка зацикливается автоматически).
2. **Положите файл поверх старого** с тем же именем:
   ```bash
   cp мой_трек_раунда.mp3     static/audio/game-theme.mp3
   cp моя_финальная_тема.mp3  static/audio/results-theme.mp3
   ```
   Либо просто замените файл в проводнике — `static/audio/game-theme.mp3`.
3. **Обновите страницу** в браузере (Ctrl/Cmd+Shift+R).

Особенности:
- Трек играет по кругу на громкости 0.5; при переходе между экранами предыдущая тема останавливается, в лобби музыка не играет.
- Если в браузере заблокирован автозапуск звука, музыка начнётся после первого касания экрана (обычно так бывает на мобильных).
- Звуковые эффекты («дзынь»/«бзз» при ловле предметов) не требуют файлов — они генерируются кодом через Web Audio API.

## ⚙️ Переменные окружения

Все настройки игры вынесены в `.env` файл. Создайте его из шаблона:

```bash
cp .env.example .env
```

### Основные переменные:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `GAME_TITLE` | `Свадебный переполох` | Название игры (<title> и на главной странице) |
| `GAME_DURATION` | `60` | Длительность игры в секундах (рекомендуется 45-90) |
| `COUNTDOWN_SECONDS` | `5` | Время обратного отсчёта перед стартом |
| `ADMIN_PASSWORD` | *(обязательно)* | Пароль для админ-действий (сброс результатов) |
| `MAX_PLAYERS_PER_ROOM` | `30` | Максимум игроков в одной комнате |

### База данных (опционально):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_URL` | *(не задана)* | PostgreSQL connection string. Если не задана — используется in-memory хранилище |

**Пример для PostgreSQL:**
```
DATABASE_URL=postgresql://user:password@host:5432/wedding_game
```

### Переменные для Docker Compose:

Используются только при запуске через `docker-compose.yml`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DB_USER` | `wedding` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | `wedding` | Пароль PostgreSQL |
| `DB_DATABASE` | `wedding` | Имя базы данных |
| `POSTGRES_PASSWORD` | `wedding` | Пароль для PostgreSQL контейнера |

> ⚠️ **ВАЖНО:** Обязательно измените `ADMIN_PASSWORD` и пароли базы данных в production!

## 🚀 Установка и настройка

### Требование: Python 3.8+

### Быстрый старт (локально)

```bash
# 1. Клонируйте репозиторий
git clone <your-repo-url>
cd wedding

# 2. Создайте виртуальное окружение
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# 3. Установите зависимости
pip install -r requirements.txt

# 4. Настройте переменные окружения
cp .env.example .env
# Отредактируйте .env и задайте ADMIN_PASSWORD!

# 5. Запустите сервер
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Откройте [http://localhost:8000](http://localhost:8000) в браузере.

### Запуск в Docker

```bash
# 1. Создайте .env файл
cp .env.example .env
nano .env  # Отредактируйте пароль

# 2. Запустите с PostgreSQL
docker compose up --build
```

Docker автоматически поднимет:
- FastAPI сервер на порту 8000
- PostgreSQL базу данных

### Деплой на Railway (облако)

Подробная инструкция в [deploy.md](./deploy.md).

Кратко:
```bash
railway init
railway up
railway domain  # Получите HTTPS-домен
```

Railway автоматически:
- Соберёт Docker образ
- Развернёт сервер с HTTPS
- Поддержит WebSocket (WSS) из коробки

### Деплой на другой хостинг

Подходит любой хостинг с поддержкой Docker:
- Heroku
- Fly.io
- Render
- Любой VPS с Docker

## Механика игры

### Игровой процесс
- **Персонаж-жених** — рисованный спрайт (цилиндр, смокинг, бабочка), масштабируется под размер экрана
- **13 видов падающих предметов** — эмодзи с яркой круглой подложкой и цветной обводкой (золотая — бонус, красная — штраф)
- **Заморозка** ❄️ — тёща, тесть и длинный тост блокируют управление на 1–1.5 сек
- **Тряска экрана** при ловле негативного предмета
- **Всплывающие индикаторы** — при ловле рядом со счётом моргает эмодзи предмета и очки (+25 / -15)
- **Процедурный звук** (Web Audio API) — синтез «дзынь» и «бзз» без загрузки аудиофайлов

### Управление
| Способ | Платформа |
|---|---|
| Палец (touchmove) | Смартфоны / планшеты |
| Мышь (mousemove) | ПК |
| Стрелки ← → или A / D | ПК (клавиатура) |

### Мультиплеер
- Комнаты по коду (несколько банкетов одновременно)
- Живой лидерборд через WebSocket
- Троттлинг очков (batching каждые 50 мс) — экономия трафика
- Автопереподключение с экспоненциальным backoff
- Честное ранжирование при равных очках (tie-breaking по timestamp)

### UI
- **Лобби** — ввод имени и кода комнаты, кнопка «Как играть» с полными правилами и таблицей предметов
- **Игра** — HUD с таймером и счётом, canvas на весь экран
- **Итоги** — таблица лидеров с подсветкой своего результата

## Архитектура

```
[ Мобильные клиенты ]
        |
        | HTTPS / WSS (Single Origin)
        v
[ FastAPI (ASGI) ]
        |
        +---- GET /            → index.html
        +---- GET /static/*    → game.js, ресурсы
        +---- WS  /ws          → игровые сессии
        |
        v
[ In-memory rooms ]  →  (опционально Redis для масштабирования)
```

- **Один origin** для статики и WebSocket — нет проблем с CORS и Mixed Content
- **Canvas 2D** вместо WebGL — совместимость со старыми WebView (Telegram, Viber, iOS Safari)
- **Delta Time** в игровом цикле — одинаковая скорость на 60 и 120 Гц экранах
- Текущая версия хранит комнаты в памяти процесса; для 100+ игроков и нескольких узлов — Redis (ZSET-лидерборды, Pub/Sub), см. [task.md](./task.md)

## WebSocket события

| Направление | Тип события | Описание |
|---|---|---|
| Client → Server | `join_room` | Подключение к комнате |
| Server → Client | `room_joined` | Подтверждение подключения |
| Server → Client | `game_start` | Старт раунда |
| Client → Server | `score_increment` | Обновление очков (batched, 50 мс) |
| Server → Client | `leaderboard_update` | Лидерборд + оставшееся время |
| Client → Server | `ping` | Heartbeat |
| Server → Client | `pong` | Ответ на heartbeat |
| Server → Client | `game_over` | Конец раунда + финальный рейтинг |
